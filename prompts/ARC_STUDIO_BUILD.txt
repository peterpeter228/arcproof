P0 scope:
- An immutable invoice contract named ArcProofInvoices.
- createInvoice(uint256 amountNative,uint64 expiresAt,bytes32 termsHash), merchant=msg.sender. ID is exactly keccak256(abi.encode(uint256 chainId,address contract,address merchant,uint256 nonce)). nextNonce starts at 0 and means the next unused nonce; created range is [0,nextNonce). nextNonce(address) and getInvoice(bytes32) are readable.
- Amount is native USDC with 18 decimals, strictly positive, <=1e18, divisible by 1e12. The UI parses decimal strings into integer microUSDC (max six fractional digits) then multiplies by 1e12. No floating point. 0.20 USDC = 200000000000000000 native units.
- expiresAt must be greater than block.timestamp and no more than seven days ahead. UI default 24h. P0 UI always creates zero termsHash (no attached terms), and blocks payment for a nonzero hash with UNSUPPORTED_TERMS. The contract retains an opaque bytes32 field; P0 does not invent a nonzero hash protocol. Optional titles are untrusted, unbound plain text (max 80 Unicode code points), never proof. Existing nonzero-hash payments may still be read and verified without claiming delivery. Never put customer PII onchain.
- Immutable merchant, amount, expiry, termsHash; paid initially false, payer/paidAt/paidBlockNumber initially zero. Only successful payment sets paid,payer,paidAt=block.timestamp,paidBlockNumber=block.number (uint256). No editing or cancel path.
- payInvoice(bytes32) payable accepts the exact invoice amount once before expiry. Use the same pinned OpenZeppelin ReentrancyGuard for both state-changing entry points. Checks-effects-interactions. Record balanceBefore=balance-msg.value. Forward exactly msg.value to the fixed merchant; receiver failure reverts. After return require balance==balanceBefore; otherwise revert. Emit InvoicePaid only after success.
- Events InvoiceCreated(invoiceId indexed,merchant indexed,merchantNonce,amountNative,expiresAt,termsHash) and InvoicePaid(invoiceId indexed,payer indexed,merchant indexed,amountNative).
- No owner/admin, upgrades, custody vault, escrow, deposit, withdraw/rescue, arbitrary call, fee, allowance, approve, transferFrom, Permit, AI adjudication, refunds, release timers, multi-chain or x402. No accepting receive/fallback. Unexpected pre-existing balances cannot be taken by payments or used to make up underpayment.
- This is atomic forwarding, not a claim that the contract never touches funds. It is not an audited or production-ready payment processor.
