## 6. 安全与协议审查

建立轻量威胁模型：资产、信任边界、攻击者、浏览器/钱包/RPC/合约/托管各自责任。优先检查会造成错误付款、重复付款、假成功、敏感泄漏、无法恢复的缺陷。

### 合约与金额
- 权限、资金去向、重入、失败回退、重复付款/创建、状态机、事件与状态一致性、意外余额/锁款、可升级/管理员风险。
- Arc 原生 USDC 的精度、原生资产与 ERC-20 表示差异、gas 币与手续费展示；依据当前官方文档核验，不沿用其他链假设。
- 金额输入/格式化/舍入/大数/单位转换、边界值、零值、超额/少额、地址和链校验、收款人与付款人的绑定。
- termsHash 等字段究竟承诺什么；基于合约/PRD确定语义，不因陌生字段就一律拒绝已有合法付款，也不把资金核验冒充完整法律条款核验。
- ABI、部署字节码、实际网络、配置与源码一致性。没有链上或编译证据时明确限制。

### 前端、钱包与恢复
- 恶意/篡改分享链接、伪造部署、恶意 RPC、XSS/依赖注入、危险导航、postMessage 来源校验、遥测/控制台泄漏、CSV 注入。
- 意图是否在钱包请求前持久化；双击、双标签、刷新、账户切换、网络切换、延迟返回、storage 损坏/拒写、Web Locks 不可用。
- success/revert/unknown 是否严格区分；未知不能自动重发、过期自动解锁或用清理缓存“恢复”。
- 交易 hash 已知/未知、被替换/取消、同 nonce、跨设备等恢复能力的真实边界。成功完成后是否正确解锁下一笔操作。
- 请求期间组件卸载或切换输入时，旧结果是否污染当前页面/导出。
- 不将修改 nonce 管理或降低 fail-closed 要求作为方便演示的捷径。

### 核验与导出
- chain/from/to/calldata/value、receipt status、block hash/number、日志地址与 index、invoice ID/amount/parties、finality 是否完整绑定。
- 日志重复/乱序/缺失、receipt 与 transaction 不匹配、RPC 部分失败、重组/最终性未知。
- “观察到的事实”“验证成功的结算”“旧调用者提供的数据”“离线模拟”是否明确分层，来源标签是否可能误导。
- JSON/CSV/打印保留精确金额、时间、费用、证据范围、失败原因与限制；Excel/Sheets 精度及公式注入。
- 内容相同不等于证明某次未知请求成功；不能只凭余额变化或一条事件认定付款完成。

每项安全发现写清前置条件、可达入口、攻击/故障步骤、实际影响、证据与最小修复。依赖漏洞需结合锁定版本、当前官方 advisory、开发/生产可达性，不把 npm audit 数量直接当实战风险或“零风险”。未经授权不向真实部署发攻击请求。

- 回归测试、验收标准、依赖/授权、工时区间、残余风险。
区分“安全缺陷”“产品/评审弱点”“未验证”，不能混为一谈。

### E. 产品与 UI 完整方案
目标用户/主场景、差异化、保留/删减/新增功能、逐页结构、设计 tokens、组件状态、具体文案、手机和可访问性方案。包含可实施的结构或伪代码，但不要伪造源文件存在或提交。

### F. 可直接交给 dot 的实施 backlog
按依赖关系拆成可独立验证的批次。每项提供：
task_id / linked_finding_ids / priority / objective / scope_in / scope_out / files_or_modules / implementation_steps / regression_tests / acceptance_criteria / dependencies / permission_needed / estimate_range / rollback / stop_condition。

另外给：

- 截止前的完成顺序与缓冲。
这些是规划上限/估算，不是假称已投入工时。未知截止时刻时不要假造倒排日期。明确人类操作时间与编码时间、外部等待和风险缓冲。
优先可逆改动，不重构已验证安全路径来追求新颖。每批提交前固定版本、验证，推送使用 expected_sha 非强制更新并回读；冲突先合并，不能覆盖他人改动。

### G. 验收与证据收集清单
完整成功和错误路径、浏览器/两钱包/只读链上验证、恶意输入、恢复、导出、构建身份及可访问演示。给明确预期结果和证据文件类型；签名/资金步骤标为需用户另行操作/批准。
保留 fail-closed、受控演示标签、原始日志及未验证项，不用清理历史失败来美化结果。

### H. 参赛材料与演示包方案
一句话介绍、150–250 字介绍、3 分钟逐段演示脚本、截图/视频清单、README 重排、评委复核路径、必备链接和发布前检查表。
只能依据已证实能力写宣传内容；未完成能力使用明确占位符，不捏造指标。给备用演示路径，但离线录屏/fixture必须标清，不能冒充实时主网成功。

### I. 最终回传给 dot 的执行说明
