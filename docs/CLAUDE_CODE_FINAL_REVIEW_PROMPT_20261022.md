## 6. 必须保持的安全不变量

从真实源码验证，不只引用此列表：

- build 固定 `testnet|mainnet`；未设置的默认与非法/空值拒绝行为保持明确。URL、localStorage、导入内容不能决定任意 RPC/链/合约。
- 生产 manifest 为空时 mainnet deployment 为 null，发送关闭。初始化不能崩溃、自动发现钱包、自动恢复连接、挂载测试网业务 RPC 或读写/清理测试网请求历史。
- 链、可信部署、runtime、账户、session generation、invoice、tx 的身份绑定不可丢失。prepared action 在账户/网络/会话改变后失效。
- hashless requesting/uncertain 请求不能靠“发票已付款”归因为原请求，不能自动释放重复发送保护；未知结果禁止自动重发。仅凭超时、刷新、清缓存或切换页面不能解锁。
- 持久记录和 Web Lock 的作用域、异常 JSON、缺失 invoiceId、跨标签并发和重复点击要 fail closed，保留原始记录供诊断。
- VERIFIED 必须来自完整身份与结算证据；不可仅凭交易存在、status=1、合约事件、浏览器截图或一个数值相同判断到账。核对 native USDC 精度、系统转账事件、receipt/block/finalized 关系、runtime 与政策；未知/冲突保持不通过。
- 原生 USDC 的 18 位链上单位与可能存在的 ERC-20 接口单位不能混用；用整数/BigInt，禁止浮点金额算账。Gas、发票金额、实收、测试币分别展示。
- 导出分类必须绑定可信 registry 与 observation scope；模拟 payer/tx/time 为 null，不伪造真实值；非可信目标为 unknown，不能通过 mode 字符串抬升为主网证明。
- 测试网/主网 explorer、币种文案、证据页、分享 URL、下载文件名相互一致。检查未来主网 ReceiptFacts 的 test USDC 文案残留，但不要为修文案提前开启主网收款。
- Clipboard 异步、A→B 导航、取消/返回、卸载、重复操作不能显示过期成功；URL 参数污染、重复 tx、非规范输入应拒绝，不能回落到可支付路径。
- XSS/恶意链接、CSV 公式注入、超长输入、DoS、敏感日志、依赖公告、CSP/外链等要按实际攻击面检查；不把 `npm audit` 全绿等同专业安全审计。

每个确认的问题至少包含文件/位置、复现、影响、修复与回归。优先补红测再修绿；没有复现的怀疑标“待验证”，不要拿模型严重级别直接当事实。

### E. 参赛包与人工关卡
把可自动做的准备做完。为未授权的实链与公开步骤提供最小、可验证的人工清单，不实际执行。主网启用必须另一个显式阶段：复查官方参数和资格、确认预算/金额/收款方/权限、真实部署与代码核验、本人签名、只读回查、最后再纳入可信 manifest，并重测。不得先开启按钮等我补资金。

不沿用无法核对的“18小时”旧上限，也不无限扩展。先估计各阶段实际工时和风险，优先有明确验收价值的改动；完成当前范围、安全门槛和回归后停止，非必要功能列后续。发现比赛资格强反证时直说，停止为了参赛而无效堆功能，仍交付可用改进。

## 9. 最终验收矩阵

每项记录 `PASS / FAIL / BLOCKED / NOT_RUN / NOT_APPLICABLE`、输入版本、命令/操作、时间与证据文件：

- 干净锁定安装/环境恢复；单元与集成；lint；types；合约 suite（可实际运行才写本轮通过）。
- 测试网和关闭的主网两套 build；非法网络 selector；各自产物 hash 与源码输入摘要。
- 只读初访、非法输入、网络超时/失败、未配置部署、旧测试网链接、重复 tx、返回/刷新/取消、长地址/金额边界。
- 离线闭环与可见模拟标识；复制成功/拒绝/延迟；JSON/CSV 实际下载及内容重读；打印/PDF 若做则检查真实分页，不做明确 NOT_RUN。
- 未决请求、损坏存储、多标签/重复点击、会话切换、非可信部署、伪造/跨范围导出。
- 375/768/1440、键盘/焦点、对比度、200%缩放、加载/空/失败状态。
- 真实钱包与主网交易独立列，不得拿 mock 或 testnet 替代。未经授权保持 NOT_RUN。
- Git SHA、source-input hash、build time、Studio同步状态、截图与测试版本一致。后续改代码必须重跑相关检查，不能引用旧绿测。

保留最初失败日志和修复后日志。不能加总重叠测试数量夸大覆盖率；不能把只运行一部分写成全量通过。

## 10. Studio 与 GitHub 的最后一公里

Ubuntu 改动产生新的源码快照后，旧 Studio 同步证据立即只代表历史版本。输出一个白名单同步清单、旧/新 hash、排除文件与验证步骤；不能写“Studio已同步”除非你确实有授权访问并完成回读。

只操作既有项目，不创建替代项目。若当前没有 Studio 访问能力，做完 GitHub/本地工作并清楚标记“待同步”。不要索要 cookie 或复制会话令牌，也不要通过 CLI 自动调用 Studio AI/部署来绕过权限。同步不能覆盖 `.env`、凭据、独有文件或原构建历史。同步后应独立下载/回读、必要时正常刷新并核对当前身份；文件一致、预览一致、整个工作区一致分别证明。

Git 交付遵循最小改动、独立分支、非强制提交，防止覆盖其他任务。推送前重读远端并处理并发；冲突不能强推。记录最终远端 SHA 与内容/CI 状态；没有运行 CI 就写未运行。不要把提交即部署的自动流程当安全无副作用操作，先核查。
