# NET-01 private release-readiness design
2026-10-21 UTC. DESIGN ONLY. Baseline 94a84c44b02d52a827bed42fc9f9a5d414619b7d, frozen code in ../argon-plan/frozen-source; official requirements in ../rules/ROUND2_ELIGIBILITY_MATRIX_20261021.md. No implementation, login, terms acceptance, publication, deployment, wallet or financial action.

## Decision and least-cost valid route
Round two does require mainnet, so current testnet-only software cannot satisfy the submission. Reuse the existing exact-payment contract and safety checks. Avoid new contract features, a general multichain dashboard, dependency migration or wholesale frontend rewrite. First close safety issues and replay real captured evidence; then introduce one immutable network context selected at build time, passed to the existing client, storage and screens. Keep testnet as default and mainnet disabled with no trusted deployment.

A separate mainnet build is cheaper and safer than arbitrary runtime chain switching. It may share components and the domain model; it must not share unscoped state. A fixed trusted registry can resolve read-only links, but cannot accept RPC/address/policy overrides from a URL or imported file. Mainnet skeleton with synthetic mocks is a private candidate, never a deployed release. Testnet-only technical demo is the fallback if owner choices or entry requirements cannot close.

## Minimum tests before claiming private adaptation complete
1. Existing testnet regression suite passes unchanged in behavior, including exact prepared calldata/value, account change, connection generation, Web Locks, storage failure and no automatic resend.
2. Same contract-looking address/invoice/hash on wrong chain is rejected. Mainnet record paired with testnet policy/client/session fails; unknown emitter/policy/finality fails.
3. Testnet intent survives mainnet selection; mainnet cannot recover/clear it. Other tabs and storage events stay scoped. Rejected before dispatch is distinguishable from post-dispatch uncertainty; no mutation without exact identity.
4. Wrong RPC chain, wrong runtime bytes, no code, stale/replaced deployment, inconsistent receipt/tx/block and unsupported finalized query remain fail-closed/read-only.
5. Native USDC decimal tests use 18-decimal integer values, not 6-decimal ERC-20 conversion. Preserve exact transfer legs, separate fee accounting, payer/merchant identity and gas-related event handling consistent with current official evidence.
6. Build-config matrix: testnet default; unsupported key rejected; mainnet configured with empty manifest cannot send; URL/localStorage/import cannot inject RPC, wallet target, chain or deployment.
7. Route matrix: valid same-network pay and receipt; other-network and malformed links; duplicate tx parameter; changes to tx/invoice/deployment invalidate displayed result and export; read-only access needs no wallet.
8. Export matrix: fixture/testnet/mainnet/unknown labels and explorer bases; imported mainnet claim cannot upgrade trust; old testnet exports retain labels; controlled demo never exported as customer revenue.
9. Candidate-bound typecheck/lint/build and targeted real-browser viewport/keyboard/zoom/print/JSON/CSV download tests. Record raw commands, versions, UTC and exit codes; mock-provider tests are not wallet/mainnet acceptance.
10. Actual mainnet acceptance remains a separate phase: exact source/runtime/deployment receipt, correct chain, known transaction/raw receipt/logs/finalized block, read-only replay, correct public app/repo/version and factual video. These tests are NOT_RUN and outside this task.
