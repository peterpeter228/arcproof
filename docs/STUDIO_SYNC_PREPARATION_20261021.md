本文件是准备材料，不证明已同步、部署、发布或参赛。本轮只在私有代码与本地/云端只读预览范围工作。

- GitHub 提交和本地构建不是 Studio 项目版本；不能仅凭 Studio 链接、页脚标识或旧截图认定当前来源合格。

## 用户批准现有项目内同步后才执行的顺序

1. 先只读查看 Studio 当前项目状态，导出或取得当前源码/测试与时间；与本次 GitHub 提交逐文件比对。保留两边版本，不覆盖未知更新。
2. 将审查修补作为明确的外部 review 输入交给 Studio：未知请求不归因、复制状态隔离、只读入口、收据层级、构建证据和测试。记录实际谁生成、谁修改、哪些测试在 Studio 重跑，不能把外部改动伪称为全程 Studio 原创。
3. 在 Studio 内完成该平台支持的编译、测试、应用预览，保留真实输出及失败记录。必要时用导出校验确认这些结果属于同一候选；没有导出证明则状态仍 unknown。
4. 核实本轮对混合开发流程的适用性。普通参赛者问答不是主办方授权；必要的对外询问须另获用户许可。
5. 仅在 Studio 来源与公开许可路径确定后，推进 NET-01 私有适配。主网 deployment/manifest 不填假地址，不迁移未知测试网 intent。参见 NET01_PRIVATE_READINESS_DESIGN.md。

## 公开与资金前独立审批点

- 公开范围与许可证：先列明要公开的第一方代码、文档、第三方许可/品牌排除，不自动将整仓标 MIT；历史原始审查和账户信息不默认公开。
- 平台条款：官方详情 https://dorahacks.io/hackathon/arc-microgrants-2/detail ，平台条款 https://dorahacks.io/legal/terms 。本文件不代表接受条款。
- 实际主网部署、签名与 USDC：逐项列出网络、地址、方法、固定金额、gas/费用上限及不可逆后果，由用户本人签名执行。不得因“提高获奖机会”代为发送资金或保证收益。
- 视频与提交：只有实际完成的 Studio 构建和主网交易能出现在完成证明中；受控两钱包须如实披露，不包装成客户收入。提交与公开动作单独获准。
