# Reviewer-probe semantic migration

This change keeps every one of the 114 standalone service-probe names, six reviewer UI-test names and 26 low-level safety checks. Nothing is skipped, deleted or hidden by a new lint ignore. Original source copies are preserved as text evidence under `evidence/quality-gates-20261021/original-*-source.txt`; the actual `.ts`/`.tsx` files remain executable and linted. Original result files outside this new evidence directory are untouched.

| Preserved test / property | Prior failure | Explicit migration and stronger check |
| --- | --- | --- |
| Duplicate submit permits one wallet send | Error matcher required the old word `unresolved`, while the atomic Web Lock returns “Another tab has a wallet operation in progress.” | Match only these two meaningful blocked states, still require exactly one wallet send, and resolve/await the first mocked request in `finally` so a failed assertion cannot poison later tests. |
| Returned hash survives lost context/storage failure | Storage was made unwritable before dispatch, but the historical assertion expected the wallet to run. That contradicts durable-before-send safety. | First require pre-dispatch quota failure to reject with zero sends. Separately turn on quota failure only from the actual mock send callback, after an intent is persisted; require a persistence error, one send, retained hash, safe cache helper, and no second send while the intent remains unresolved. |
| Coherent partial receipt remains unverified | The old fixture omitted transaction inclusion metadata, so it failed before reaching the intended settlement boundary. The checked deployment now has a native-settlement policy. | Add consistent synthetic transaction block hash/number/index and log index provenance. On the checked deployment, missing native legs must return `INVALID_NATIVE_TRANSFER` and `verified=false`. Also explicitly call the same verifier/RPC adapter with a copied legacy deployment lacking a policy, retaining the original `UNVERIFIED_ARC_EVIDENCE`, false flag and payment-log-index assertions. The historical test title remains as an identifier, not a claim about current checked-deployment status. |
| Returned invoice is the same verified snapshot | Same incomplete fixture and obsolete generic no-policy status. | Preserve exact read-count and snapshot-expiry assertions. Require the current missing-native-leg failure and false verified flag. No imported success is trusted. |
| Saved receipt binds exact call; reverted receipt releases lock | Historical transaction fixture had no inclusion block/index identity required by the current recovery contract. | Supply matching synthetic inclusion metadata, retain both original recovery assertions and all mutated sender/target/hash/function/invoice rejection cases. No real chain values are fabricated: this is explicitly mock evidence. |
| Each mutated receipt identity/provenance field fails before settlement | A generic “not UNVERIFIED_ARC_EVIDENCE” assertion could pass merely because native legs were already missing. | In addition to false verification and the old assertion, require every mutation to fail before `INVALID_NATIVE_TRANSFER`. This prevents the baseline missing-leg failure from masking an ignored identity/provenance mutation. |
| Unsupported payment route cannot invent an invoice or prompt a wallet | The old disabled wallet button was intentionally removed by UI-03. | Retain missing amount/recipient assertions; require immediate no-wallet explanation, no buttons, safe home link, no account/connect mock calls and no fetch. |
| Unsupported receipt cannot verify/export | The old fake-wait button and “Pending” status were intentionally removed. | Require immediate unavailable/unsupported state, explicit nothing-awaited message, no Pending/Verified label, no buttons/proof export, no wallet calls and no fetch. No 450ms wait is used to manufacture a state. |
| Low-level safety probe result integrity | Script historically printed false results without a failing exit status. | Preserve all 26 checks, count cases/failures, and return nonzero whenever a check is false. |

## Evidence sequence

1. Original versus concretely typed/offline-transport harness on unchanged production source, with identical current browser prerequisites: 104 passed / 10 failed, same 114 names and outcomes. This isolates the lint refactor from functional behavior.
2. Focused validation-before-write fix, plus correct test cleanup/address canonicalization: 108 passed / 6 failed. This exposed remaining historical semantic assumptions rather than clearing unknown intents.
3. The migration above, against a separate validation copy containing only the integrator's `walletIntents.ts` production fix: 114 passed / 0 failed, zero global fetch attempts. The invalid-input persistence regression changes from failed before fix to passed after fix. Migrated reviewer UI: 6/6; low-level safety: 26/26.
4. The integration coordinator must rerun these exact suites with the final dependency/export/UI patches before calling the combined candidate accepted. Historical names and outcome counts are compared in `report.json`; fresh source hashes bind the tests to this migration.

The same test count is not a claim of equivalent or independent coverage. The table describes what changed and why. Synthetic receipts, deterministic locks and jsdom are not a real browser, real wallet, current RPC/finality evidence or professional audit.
